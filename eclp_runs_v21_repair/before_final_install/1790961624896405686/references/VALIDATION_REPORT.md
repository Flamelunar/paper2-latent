## 2. 本轮重点新增测试

本轮新增/重跑的机制检查覆盖：

- `no_error` 仍使用新观察，只移除预测误差；完整校正器会使用该误差。
- 状态缓存不能跨场景复用；私有目标不参与公共状态身份。
- 场景重排/分片不改变 RNG；动作与环境随机流不同。
- 联合高斯 log-density 与 `torch.distributions.MultivariateNormal` 对齐；非法协方差/非有限值拒绝。
- 更新后 KL 越界时恢复**参数与 Adam 主副本/矩状态**；固定动作不随新均值移动。
- 成本账本保留失败和中断请求，不将其当作未发生。
- `offset` 支持 F 未参与拟合的场景验证；F 目标只用共同动作前历史和对方回复。
- 统计 compare 也不能向原基线目录写输出。
- within-H 的三值聚合：成功、失败、unknown；原主指标的 ever 聚合成为默认。
- `policy_B` 与 `B` 在四种 state mode 下保持相同数值；public loss 不更新 predictor/readout 前缀，校正路径梯度契约按 mode 区分。
- 多轮校正仍保留历史 correction 的 public 梯度；ECLP 的 error projection 有梯度，`no_error` 的 error projection 无梯度。

旧 v1 测试在本轮环境重跑为 56 项、55 通过、1 可选源路径测试跳过；未机械沿用旧报告中的“0跳过”。新版将源路径改为 `ECLP_SOURCE_ROOT` 并执行实际快照检查，仍保留1项真实 HF 依赖不足的跳过。

## 3. 生产验收仍要完成

按 README 的 `smoke` 在服务器执行：固定基础模型与 Persuadee、真实 BF16 前向/反向、公开与状态梯度隔离、一次公开生成、一次模拟器实际回应及状态更新。

之后按 P2 进行最多200 optimizer steps 的训练与固定 dev 检查。出现未来标签泄漏、环境不兼容、行为密度不匹配、模型身份变化、空公开输出或不可解析的关键奖励时，应保留失败记录并停止，不通过换精度/模型/测试样本让任务看起来完成。

当前实现采用失败停止策略；它不是一个已经覆盖所有部署异常的生产服务。正式生成出现失败案例时，不得跳过并改分母，也不得把缺失回复自动补成成功；修复后以同一锁定协议重新执行相应完整场景。
