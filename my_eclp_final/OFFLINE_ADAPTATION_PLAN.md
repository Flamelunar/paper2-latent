# 当前方法：ECLP 状态纠错 + 离线隐式策略优化

本修订取代旧方案中的真实对话 effect 探测和交互奖励 RL。
SFT 与最终测试的模型、原始数据、生成和 Judge 协议保持现有约定。
训练全部在物理 GPU4 上运行，网络 BF16，不使用量化；高斯密度、
损失汇总和优化器主状态继续使用 FP32。

## SFT 的研究判断

保留现有公开回复、观察预测、策略对齐和权重 0.1 的 ISR reasoning
辅助监督。它允许利用原数据中的教师推理进行蒸馏，部署时仍只输出
公开劝说回复。该设定可能改善初始化，但尚无对照实验支持“必然更好”。

LatentR³ 原文强调不需要 CoT 数据，因此本文不得声称同样是无 CoT
监督。本方法是受 LatentR³ 启发的任务适配，不是完全复现。正式论文
需用 reasoning_weight=0 的匹配对照衡量辅助监督贡献；没有执行该
对照前，不把蒸馏收益归于状态结构或 RL。

继续训练全部 59,868 会话、10,000 个场景的一个 SFT epoch，共 7,484
次优化更新。原 SFT optimizer、随机数状态、数据游标和 checkpoint
继续使用。不得为离线 RL 改动正在运行的 eclp_elpo.py。

## 来源论文与优化器的边界

来源为 ICLR 2026《Reinforced Latent Reasoning for LLM-based Recommendation》
§3.2.2，公式 (5)–(8)：连续高斯采样、负参考答案 PPL、批级优势，
以及冻结语言骨干、更新 LatentRATT。它无需自回归答案采样。

本实现使用已有 ECLP 的 64 维连续策略动作和冻结的 latent 执行映射，
以联合高斯动作密度作策略比率、SFT 策略作参考，并保留 trust-region
保护。因此这是离线连续动作策略优化，不冒称逐行复现原 LR-GRPO。
冻结语言骨干并不自动意味着条件输出分布的 KL 为零；这里记录的
KL 明确定义在动作分布，不能写成文本 KL。

## 连续奖励与劝说任务适配

每条数据已有场景、劝说目标、公开对话历史以及 gold_response。
正确回复的平均 token NLL（包括 EOS，沿用当前目标截断）定义为
ℓ+(a)。它通过 teacher forcing 计算，不生成回复。

保留相同公开历史，从最新实际 persuadee 反馈到达前的同一状态分支，
仅将该次更新的预测误差置零，继续读取同一反馈，得到对应的 ℓ−(a)。
这与删除反馈、删除历史或改变目标不同；所有状态网络权重仍然冻结。
两个分支使用相同候选动作 a。无历史反馈的首轮不启用该项。

令 d(a)=ℓ−(a)−ℓ+(a)，a_ref 为冻结 SFT 策略在完整当前上下文下的动作。
默认奖励为：

R(a) = −ℓ+(a) + λ tanh(d(a)−d(a_ref))，λ=0.1。

第一项为 −log PPL，提供连续的答案拟合信号，避免负 PPL 的指数放大
和溢出。第二项奖励比 SFT 参考更能利用预测误差纠错的候选，并通过
tanh 和小权重限制其影响。参考动作的 bonus 恒为零；首轮 bonus 为零。
中心化和有界化不是有效性的保证，仍可能偏向当前数据的参考措辞，
也可能利用 counterfactual 分支的弱点。主 NLL、分项诊断与独立测试
必须分别报告。不能把这个奖励称为实际劝说成功回报或因果效果估计。

同上下文的优势使用 R(a_i)−R(a_ref)，以当前收集批的离散程度归一化
（下界 1e−3，上下界裁剪至 ±10）。候选动作、协方差、旧概率在一次
更新中固定并 detach；动作维度的联合 log density 求和而非平均。

提供 reward=ppl / nll / correction 三个开关。pure PPL 是原奖励形态的
对照；本优化器与原论文不同，不能将其结果直接称为原 LR-GRPO。

## 数据与预算

原 preference 数据 2,000 条：已固定 200 条 dev、1,800 条 RL train。
RL 完整使用 1,800 个场景一次，每个上下文 4 个随机高斯候选加 1 个
SFT 参考。每批 64 个场景收集后更新，下一批从刚更新的策略重新采样，
避免把全体候选长时间当作当前策略样本。

每条计算 5 个 factual NLL；只有具备历史反馈的 1,455 条计算另外
5 个 counterfactual NLL。总计 16,275 个 action/state 的离线答案评分，
采用单条教师强制前向；另外有原历史 replay/context 编码成本。
预检发现 GPU BF16 批量路径与原单条路径有约 0.013 的 NLL 差异，
因此当前不启用批量答案评分，避免数值差异污染小幅 latent 奖励。
重复次数为 1，RL 数据 pass 为 1；每批小策略网络最多更新 2 epoch，
学习率 1e−5，update batch 为 1，沿用现有行为密度与 KL 检查。
若某步因更新后的 KL 超限而回滚，则将学习率减半重试，最多 7 次，
下界 1e−7；每次尝试的实际步长与 KL 都保留。已经超出参考 KL 的
行为策略不通过降低步长掩盖，仍会停止并留下诊断。

任何训练中的 Persuadee 调用、Judge 调用、自回归 generate 均抛错。
原 effect predictor、在线探测和三轮真实对话 RL 不进入此训练流程，
因此论文也应撤去它们对应的“真实反馈学习探索几何”主张。

## 断点、检查与质量条件

每个 64 场景的批更新后保存策略、optimizer、RNG、数据游标和完整
reward 分项。checkpoint step 在离线 RL 中表示已提交场景数，另记
optimizer_updates；不得将它与 SFT step 混用。
中断后从最近提交的批继续；未提交的短批在新 attempt 重做并保留
旧诊断与成本。实际策略须发生改变，执行器哈希须不变，优势不能全零。

先在现有已提交 checkpoint 上执行 GPU 机制诊断，检查：实际奖励
非零、批量 NLL 与原标量实现一致、行为密度重放、策略更新、冻结
组件不变以及禁止生成的接口。这不属于性能结果。

RL 结束后在原 200 条 dev 上比较最终策略与冻结 SFT 参考的平均 NLL
及纠错增益。平均 NLL 恶化超过 0.05 即暂停后续测试并保存诊断。
这个 gate 只排查代理任务的明显退化，不能证明真实成功率提升。
最终 checkpoint 固定为完整一遍 RL 后的最后已提交 checkpoint；
不通过测试集选模型。

## 最终评估与论文证据

继续对原 index 0–999 的 1,000 个场景生成完整五轮对话。最终测试仍
使用原固定 Persuadee；它仅在生成阶段被调用，不参与 RL 获取奖励。
最终由 Selene-8B、Qwen3-14B 按既定协议分别评分，填写 Qwen2.5 表的
两条 Our 行，保留所有原始生成、Judge 输出及表格备份。

正式研究结论至少需要：相同监督/参数/预算的状态结构对照；
reasoning 辅助监督消融；PPL、NLL、纠错奖励比较；固定公开历史的
状态干预；多 seed 与最终双 Judge 结果。这里实现了奖励开关与记录，
尚未完成这些对照，不能提前宣称 CCF A 水准或提升。
