# Qwen2.5-7B：w/o G 与 w/o R 消融实验

## 对照与版本

完整Ours：eclp_runs_gpu4/offline_rl/checkpoint-001800；w/o G：eclp_runs_gpu4/sft_full/checkpoint-007484。后者是联合SFT，保留state network、strategy policy、virtual-token mappings与LoRA，不使用普通基线SFT。checkpoint_provenance.json记录文件SHA256、参数配置和checkpoint ID；test_ids.json记录固定192个原始index与scenario ID。训练及开发数据不变。

精确历史生成脚本seven_methods_192/generate_direct.py与主表生成manifest SHA256一致（0c513888e5f28dda939bc78b12ff92deaa6352f4ffce58323d329f6dadf2223c）。actor仍读取背景、目标、当前公共历史；仅输出公开劝说，不输出理由。均值latent action；seed=42；batch=2；temperature=.95，top_p=.7，top_k=50，max_new_tokens=512；BF16无量化；prompt预算6144。

本次公共生成合同修正：模拟器删除显式目标，只读背景和公共历史，遵循本次用户附件约束。模拟器仍为Qwen3.5-9B-persuadee/merged；完整Ours重新生成及评分，原main_experiment_table.md不覆盖。因原表模拟器含目标，本次分数须与本次重新生成的完整Ours对比。请求格式重试仍使用原规则。单场景生成在原三次重试仍失败时，保留真实已完成回合和失败原因，继续其余固定测试场景；不静默丢弃，不合成缺失回复。

## w/o R（KL-only）

SFT策略与reference严格同参数；唯一损失为beta=.02乘同协方差高斯解析KL(pi||SFT)。action width=64、std=.0625；hard behavior KL bound=.1；optimizer为原FP32MasterAdamW、lr=1e-5、weight_decay=0、全新momentum；仅policy参数可训练，dropout=0。关闭NLL奖励、correction bonus和clipped reward policy loss；不进行在线对话、reward打分或自回归生成。

保留1800个训练context、四个候选对应的重复输入、两次update epoch、update batch=64的预算。原LPO记录曾从batch=1续跑为64，见continuation_manifest.json；这里明确按最终续跑配置64执行，不声称原214次实际更新与完整预算相同。原hard-KL可能提前停止，因此实际optimizer更新数由验证日志记录。

context由冻结LoRA、state及readout和已有训练公共历史得到，ECLPRunner.context不读取policy。核验SFT/full executor hash一致和各已提交batch.pt哈希后复用context；不复用原奖励、advantages、old action means或reference前向输出。本次从SFT重新前向计算policy/reference。逐更新记录KL、总loss、梯度范数、参数最大差值及冻结reference。检查FP32 master、momentum和最终policy hash，只有完整预算均严格零漂移才允许复用w/o G生成/评分；否则报错停止并记录，不为分数不同引入其他损失。

## 评分与统计

评测器Selene-1-Mini-Llama-3.1-8B及Qwen3-14B，物理GPU4，BF16，无量化。复用主表seven_methods_192/protocol.py与win_rules.json，未使用DeepSeek混合协议或最新v3。Success五轮任一轮接受精确目标；Win@1只比较首轮公开回复与首轮gold，A/B和B/A胜/平/负=1/.5/0，场景内先平均。测试参考不进入actor或模拟器，不评Win-Full。

所有192场景纳入Turn，首次成功轮或失败5；缺失判断且无已确认成功也记5并单独报告unknown_scenarios_counted_as_5。Success主列按全部已评场景分母，缺失且无确认成功不算成功，另列success_effective_n披露判断完整有效数；Win@1无解析值不计其有效分母并报告失败数。原主表实现对Success/Turn排除缺失场景，因此本次聚合明确区分，不能静默混用。中途partial不作为正式192条结果。

## 执行及交付

supervise.py顺序：w/o G两条机制检查→完整192生成→KL-only验证→完整Ours重新生成→w/o G两Judge并行→完整Ours两Judge并行→等价复用w/o R。另有early_evaluate.py在生成过程中对已提交的w/o G记录分批评分，先Selene后Qwen3；最终评估复用逐请求缓存，并等待对应早期评分进程结束，避免重复评分。所有模型进程仅设置CUDA_VISIBLE_DEVICES=4；日志里的逻辑cuda:0/GPU0映射到物理GPU4。

commands.jsonl记录实际命令；experiment_manifest.json、checkpoint_provenance.json、test_ids.json记录来源；各variant/generation/与judges/包含逐场景生成、公开历史、原始Judge判定和提示词缓存。wo_r_kl_only/diagnostic.json、updates.jsonl、reuse_manifest.json保存退化证据；验证后该variant的generation/judges链接到w/o G，并非独立测量。

正式汇总：exp_code_ljj/results/ablation_qwen25_192.csv及ablation_qwen25_192.md。主实验checkpoint、原始训练数据、主表及既有记录不覆盖。未启动GPT-6-luna附加评分，优先完成明确要求的两位本地Judge。

## 机制检查的实际发现与失败处理

w/o G在原三次格式重试后仍有计划叙述。保留initial_mechanism_request_trace.jsonl与原manifest，不把计划当公共劝说；新实现逐场景记录失败原因和已完成的真实公共回合并继续其他场景。五轮完整性在generation_failed_scenarios和generation_missing_goal_rounds中明确披露。缺失回合不会合成回复或送Judge；仍按全场景分母报告Success/Turn，另披露有效数。Win@1在已有真实首轮回复时可评分，无首轮则记未评。解析失败与生成缺失回合分别计数。这个失败处理同时应用完整Ours与消融，不修改提示词、三次重试、参数或训练权重。

## 最终核验与本地交付

finalize.py --watch监控本次supervisor的实际PID及终态；只有完整生成、两位Judge全部完成且audit.py核验通过后才生成交付校验和。它从原始逐场景judgments重新计算六行Success、Win@1和Turn，核对checkpoint文件哈希、提示词哈希、测试ID和KL-only复用链接，并输出requirement_evidence.json与delivery_sha256.json。评分缺失和生成缺失均在CSV及Markdown中披露。

experiment_manifest.json保留实际执行时的source_files哈希；final_delivered_code_sha256单独记录最终交付版本。运行中的旧supervisor未被重启；finalize.py重新调用report()应用补充了有效分母和KL等价说明的表格输出逻辑。该修改不改变生成、评分提示词、原始Judge记录或指标公式。

本地download_final.py仅在完成核验后下载全部记录和消融代码，并逐文件核对SHA256，生成Qwen2.5两项消融实验.zip。不下载模型权重；KL-only复用关系单独说明，不把复用数据伪装为独立测量。
