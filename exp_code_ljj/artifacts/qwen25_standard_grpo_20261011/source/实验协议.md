# Qwen2.5：普通 SFT+GRPO 与 ECLP

## 要交付的真实结果

- 两个方法在固定192条场景上的 Selene Success、Win@1、Win-Full、Turn。
- Lifestyle（36）、Education（29）、Career（19）、Business（18）的同四项指标；多领域场景允许组间重叠。
- 一轮训练的分钟数，分开记录 SFT、第二阶段优化和合计。记录硬件、实际处理样本数、更新次数、计时起止及中断情况。

## 公共设置

Qwen2.5-7B-Instruct，BF16，无量化。保留原训练/开发划分及训练数据，测试只使用原始 history=[]、target_turn=1 的固定192个索引。五轮模拟对话使用每个方法自己的生成历史。沿用原主表 `seven_methods_192_20261006` 的模拟器、输入协议、回复提示词和 Selene 评分协议；该历史模拟器可见目标，不能混入后来目标隐藏版本。

公共生成配置：seed=42，temperature=0.95，top_p=0.7，top_k=50，max_new_tokens=512。参数需从实际运行配置逐项锁定。原版 Success/Turn 的缺失处理规则及各指标有效分母须随结果报告。

普通 SFT 必须是仅公共回复监督的语言模型，不得把 ECLP 联合 SFT 的 LoRA 改名充当普通 SFT。ECLP 保留状态、策略、映射模块和原离线 latent-policy optimization。

## 普通 GRPO 的定义

动作是采样的劝说文本，更新语言模型 LoRA；每个训练上下文采样4个候选，按组归一化奖励计算优势，采用 clipped token-policy objective 和固定 SFT reference。训练上下文沿用 ECLP 的1800条，不使用测试参考或测试评分选择 checkpoint。

采用模拟器回应后的目标接受/推进奖励：none=0、engagement=1/3、conditional=2/3、accepted=1，使用历史目标判定提示词。训练 judge 为配置中 Qwen3.5-9B，最终评测仅 Selene。训练奖励与 ECLP 的离线 NLL/纠正奖励明确区分。actor 格式无效记0并记录；模拟器或 judge 三次重试仍失败则中止未提交 block，不能把基础设施故障填为0。

文本 GRPO 用同一公共训练 prompt，每组4条回复进行组内奖励归一化，按每条回复的 token 均值计算 clipped loss，beta=0.02、clip=0.2、lr=1e-5。保留64上下文/block、64动作/update、2次update epoch。reference 是独立加载且冻结的同一个普通 SFT adapter。沿用 FP32MasterAdamW（BF16参数，FP32 master与优化器状态），仅更新 policy LoRA。

每组4条 actor 回复和模拟器回复批量推理，使用历史 RowSampler 的每行独立CUDA随机数发生器，保持每个候选的 seed、temperature、top_p、top_k 与512-token上限。judge 首次按组批量评分，格式错误时仅重试对应候选，并沿用历史当前回复摘录枚举约束恢复格式；目标判断提示词和奖励映射不变。BF16批量矩阵运算可能与单条产生舍入差异，因此运行manifest记录该批量实现，不声称逐token完全一致。

行为 KL 约束仍为0.1，使用每条采样回复上 K3(old||current) 的 token 均值估计，检查mini-batch最大值，越界回滚参数和优化器并沿用 ECLP 的学习率退避设置。它是采样估计，不能声称与 ECLP 的解析高斯 KL 具有相同精度。固定 reference 的 soft KL 使用常规 GRPO K3(current||reference)。

## 当前已核实的计时问题

ECLP `offline_rl/summary.json` 的4727.3519秒是某次续跑 invocation，不能当作完整1800条一轮耗时。历史训练发生过 policy_update_batch 从1到64的变化；不得声称历史整轮都采用64。需审计各段日志和提交记录；证据不足则另建统一配置的完整计时运行，保留旧结果和 checkpoint。
